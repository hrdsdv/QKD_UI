# Описание модулей и пользовательского интерфейса системы QKD

## 1. Модуль взаимодействия с QKD-устройством (qkd_interaction.py)

Модуль `qkd_interaction.py` реализует взаимодействие с квантовым устройством распределения ключей (QKD). Данный модуль использует библиотеку `serial` для подключения к устройству через последовательный порт (USB/COM), библиотеку `socket` для установки TCP-соединения между двумя абонентами, а также стандартные библиотеки Python `threading` и `time` для управления потоками и временными задержками. Модуль обеспечивает чтение сырых данных от QKD-устройства в формате битов и базисов, сохраняет их в базу данных через класс `DatabaseManager`, и поддерживает синхронизацию между двумя станциями через TCP-канал. Основная функциональность включает методы `connect_serial()` для подключения к устройству через последовательный порт, `connect_tcp()` для установки сетевого соединения между абонентами, `read_qkd_data()` для чтения данных от устройства, и `save_raw_data()` для сохранения последовательностей в таблицу `raw_data`. Модуль также предоставляет методы `start_generation()` и `stop_generation()` для управления процессом генерации ключей, а также методы `get_raw_data()` и `get_last_sequence()` для получения сохраненных данных из базы данных.

## 2. Модуль постобработки ключа (key_postprocessing.py)

Модуль `key_postprocessing.py` реализует протокол BB84 для квантового распределения ключей между двумя абонентами. Данный модуль использует библиотеку `requests` для HTTP-коммуникации между серверами, а также класс `DatabaseManager` для работы с базой данных. Основная задача модуля заключается в сверке базисов между абонентами A и B, формировании просеянного ключа (sifted key) путем отбрасывания битов с несовпадающими базисами, расчете QBER (Quantum Bit Error Rate) для оценки качества квантового канала, и проверке порога QBER, который установлен на уровне 11% - при превышении этого порога система запрашивает повторную генерацию ключа. Модуль содержит класс `KeyPostprocessingModule`, который инициализируется с путем к базе данных и URL удаленного сервера для получения данных другого абонента. Ключевые методы модуля включают `get_local_sequence()` для получения локальной последовательности из базы данных, `get_remote_sequence()` для получения последовательности от удаленного абонента через REST API, `sift_key()` для выполнения сверки базисов и формирования просеянного ключа, и `calculate_qber()` для расчета коэффициента ошибок. Модуль также обеспечивает синхронизацию данных между двумя серверами через HTTP-запросы.

## 3. Модуль восстановления ключа (key_recovery.py)

Модуль `key_recovery.py` реализует коррекцию ошибок в квантовых ключах с использованием кодов Рида-Соломона. Данный модуль использует библиотеку `reedsolo` для реализации алгоритма Рида-Соломона, который применяет алгоритм Берлекэмпа-Месси для поиска и исправления ошибок в ключевых последовательностях. Модуль также использует классы `GOSTHash`, `GOSTCipher` и `AESCipher` из модуля `gost_cipher` для хэширования и шифрования данных, а также `DatabaseManager` для работы с базой данных. Процесс восстановления ключа включает разбиение ключевой последовательности на блоки размером 32 байта, кодирование одного из ключей с добавлением избыточной информации (10 проверочных символов, что позволяет исправить до 5 ошибок), передачу избыточной информации по открытому каналу между абонентами, декодирование и исправление ошибок на стороне получателя, и проверку корректности восстановленного ключа через хэш-функцию ГОСТ Р 34.11-2018 (Стрибог). Модуль содержит класс `KeyRecoveryModule` с методами `recover_key()` для выполнения процесса восстановления, `encode_reed_solomon()` и `decode_reed_solomon()` для кодирования и декодирования данных, а также методы для синхронизации данных между абонентами через REST API.

## 4. Модуль управления ключами (key_management.py)

Модуль `key_management.py` обеспечивает управление жизненным циклом всех ключей в системе, включая их хранение, ротацию и уничтожение. Данный модуль использует библиотеку `sqlite3` для работы с базой данных, библиотеку `Crypto.Cipher.AES` и `Crypto.Random.get_random_bytes` из пакета `pycryptodome` для шифрования ключей с использованием AES-256-GCM, а также стандартные библиотеки Python `os` и `datetime` для работы с файловой системой и временными метками. Модуль содержит два основных класса: `SecureKeyStorage` для защищенного хранения ключей в зашифрованном виде с использованием мастер-ключа, и `KeyManagementModule` для управления жизненным циклом ключей. Класс `SecureKeyStorage` реализует методы `store_key()` для сохранения ключа в зашифрованном виде, `retrieve_key()` для извлечения и расшифровки ключа, `mark_as_used()` для пометки ключа как использованного в соответствии с политикой одноразового использования, и `destroy_key()` для безвозвратного уничтожения ключа путем перезаписи данных случайными байтами. Класс `KeyManagementModule` предоставляет методы `store_quantum_key()` для сохранения квантового ключа в защищенное хранилище, `get_key_for_encryption()` для получения ключа для шифрования, `use_key()` для использования ключа, `destroy_key()` для уничтожения ключа, и `get_available_keys()` для получения списка активных ключей. Модуль также обеспечивает форматирование данных для пользовательского интерфейса через методы `get_incoming_messages()` и `get_sent_messages()`, которые преобразуют данные из базы данных в формат, удобный для отображения в веб-интерфейсе.

## 5. Модуль шифрования по ГОСТ (gost_cipher.py)

Модуль `gost_cipher.py` реализует алгоритмы шифрования и хэширования в соответствии с российскими стандартами ГОСТ Р 34.12-2018 "Кузнечик" и ГОСТ Р 34.11-2018 "Стрибог". Данный модуль использует стандартные библиотеки Python `os`, `struct` и `hashlib` для работы с байтовыми данными и вычисления хэшей, а также библиотеки `Crypto.Cipher.AES` и `Crypto.Random.get_random_bytes` из пакета `pycryptodome` для дополнительного шифрования. Модуль содержит реализацию блочного шифра "Кузнечик" с использованием S-box (таблицы замен) и линейных преобразований в поле Галуа GF(2^8), реализацию хэш-функции "Стрибог" для вычисления криптографических хэшей, и классы `GOSTCipher`, `GOSTHash` и `AESCipher` для предоставления высокоуровневого интерфейса к этим алгоритмам. Класс `GOSTCipher` реализует шифрование в режиме CTR (Counter Mode) с использованием алгоритма "Кузнечик", обеспечивая потоковое шифрование данных произвольной длины. Класс `GOSTHash` реализует хэш-функцию "Стрибог" для вычисления хэшей длиной 256 или 512 бит, которые используются для проверки целостности данных и ключей. Класс `AESCipher` предоставляет дополнительное шифрование с использованием AES-256-GCM для защиты мастер-ключей в системе хранения ключей.

## 6. Модуль шифрования сообщений (message_crypto.py)

Модуль `message_crypto.py` обеспечивает шифрование и дешифрование текстовых сообщений и файлов с использованием квантовых ключей, полученных от QKD системы. Данный модуль использует стандартные библиотеки Python `os`, `base64`, `time`, `json` и `datetime` для работы с файлами, кодированием данных, временными метками и сериализацией, а также классы `GOSTCipher` и `GOSTHash` из модуля `gost_cipher` для шифрования и хэширования, класс `KeyManagementModule` для получения ключей из защищенного хранилища, и класс `DatabaseManager` для сохранения сообщений в базу данных. Полный цикл работы модуля включает получение квантового ключа из защищенного хранилища через `KeyManagementModule`, шифрование текста или файла с использованием ГОСТ Р 34.12-2018 "Кузнечик" в режиме CTR, вычисление хэша зашифрованных данных для проверки целостности, отправку зашифрованных данных получателю через REST API, пометку ключа как использованного в соответствии с политикой одноразового использования, дешифрование на стороне получателя с проверкой хэша, и уничтожение ключа после использования. Класс `MessageCrypto` предоставляет методы `encrypt_message()` для шифрования текстовых сообщений, `encrypt_file()` для шифрования файлов, `decrypt_message()` для дешифрования текстовых сообщений, `decrypt_file()` для дешифрования файлов, `get_encrypted_message()` для получения сообщения из базы данных, и `mark_message_as_read()` для пометки сообщения как прочитанного.

## 7. Модуль работы с базой данных (database_utils.py)

Модуль `database_utils.py` обеспечивает абстракцию для работы с базой данных SQLite, предоставляя единообразный интерфейс для всех модулей системы. Данный модуль использует стандартную библиотеку Python `sqlite3` для работы с базой данных SQLite, библиотеку `os` для работы с путями к файлам, и модули `logging_utils` и `timezone_utils` для логирования и работы с временными зонами. Класс `DatabaseManager` инкапсулирует всю логику работы с базой данных, включая выполнение SQL-запросов, обработку ошибок, логирование операций, и преобразование результатов запросов в словари Python для удобной работы с данными. Основные методы класса включают `execute_query()` для выполнения произвольных SQL-запросов с параметрами, `get_user_by_username()` для поиска пользователя по имени, `register_user()` для регистрации новых пользователей, `add_key()` и `update_key_status()` для управления ключами, `add_message()` для сохранения сообщений, `get_incoming_messages()` для получения входящих сообщений с фильтрацией по получателю и статусу шифрования, `get_sent_messages()` для получения отправленных сообщений с фильтрацией по отправителю и наличию поля plaintext, `add_log()` для добавления записей в системный журнал, и `get_system_logs()` для получения системных логов. Модуль также обеспечивает обработку ошибок базы данных с логированием и преобразование результатов запросов в формат словарей для удобной работы в других модулях.

## 8. Модуль сетевого интерфейса (network_interface.py)

Модуль `network_interface.py` предоставляет функциональность для безопасной сетевой коммуникации с использованием TLS/SSL шифрования. Данный модуль использует стандартные библиотеки Python `ssl` и `socket` для создания защищенных сетевых соединений. Класс `SecureNetworkInterface` реализует TLS-сервер для обработки сетевых запросов с использованием сертификатов и приватных ключей. Методы класса включают `start_server()` для запуска TLS-сервера на указанном хосте и порту, и `handle_connection()` для обработки входящих соединений. Модуль предназначен для обеспечения дополнительного уровня безопасности при передаче данных между абонентами, хотя в текущей реализации основная коммуникация осуществляется через HTTP REST API.

## 9. Модуль сетевого обмена (network_exchange.py)

Модуль `network_exchange.py` обеспечивает сетевой обмен данными между абонентами через HTTP-запросы. Данный модуль использует библиотеку `requests` для выполнения HTTP-запросов к удаленным серверам. Модуль предоставляет функциональность для синхронизации данных между двумя абонентами, включая передачу последовательностей, ключей и других данных, необходимых для работы QKD системы.

## 10. Утилиты системы (utils/)

Директория `utils/` содержит вспомогательные модули для работы системы. Модуль `logging_utils.py` обеспечивает централизованное логирование всех операций системы с записью в файлы и базу данных, используя стандартную библиотеку Python `logging` и класс `DatabaseManager` для записи логов в базу данных. Модуль `timezone_utils.py` предоставляет функции для работы с временными зонами, включая преобразование времени в московский часовой пояс, форматирование дат и времени для отображения в пользовательском интерфейсе, и генерацию SQL-выражений для работы с временными метками в базе данных. Модуль `crypto_utils.py` содержит дополнительные криптографические утилиты, если таковые имеются в системе.

## 11. Пользовательский интерфейс

Пользовательский интерфейс системы реализован с использованием веб-технологий на основе фреймворка Flask для серверной части и HTML/CSS/JavaScript для клиентской части. Интерфейс использует фреймворк Tailwind CSS версии 2.2.19, подключенный через CDN, для стилизации элементов и создания современного адаптивного дизайна. Основной шаблон `index.html` содержит структуру веб-страницы с верхней панелью навигации, боковой панелью для дополнительных функций, и основной областью контента с вкладками для различных разделов системы.

Верхняя панель навигации отображает название системы (Абонент А или Абонент Б), информацию о текущем авторизованном пользователе, кнопку выхода из системы, и индикатор QBER (Quantum Bit Error Rate) с цветовой индикацией качества квантового канала - зеленый цвет для QBER до 4%, желтый для QBER от 4% до 10%, и красный для QBER выше 10%. Боковая панель содержит кнопки для доступа к различным функциям системы, включая режим тестирования, выбор сырого ключа, выбор восстановленного ключа, и журнал операций.

Основная область контента разделена на вкладки "Главная" и "База данных" (доступна только для администраторов). На вкладке "Главная" расположены текстовое поле для ввода сообщения, кнопка для прикрепления файлов, кнопка "Зашифровать и отправить" для отправки зашифрованных сообщений, и два блока для отображения сообщений - "Отправленные" слева и "Входящие" справа. Каждое сообщение в блоке "Входящие" отображает информацию об отправителе, времени отправки, типе сообщения (текст или файл), зашифрованное содержимое с указанием размера, и кнопку "Дешифровать" для расшифровки сообщения. Каждое сообщение в блоке "Отправленные" отображает информацию о получателе, времени отправки, типе сообщения, и кнопку "Просмотр" для просмотра деталей отправленного сообщения, включая оригинальный текст сообщения.

Модальные окна используются для отображения дополнительной информации и взаимодействия с пользователем. Модальное окно выбора ключа отображает таблицу с доступными восстановленными ключами, их статусами (Активен, Использован, Уничтожен), и датами создания, позволяя пользователю выбрать ключ для шифрования. Модальное окно режима тестирования позволяет генерировать тестовые последовательности с заданным уровнем QBER для эмуляции работы реальных QKD-устройств. Модальное окно информации о сообщении отображает детальную информацию о сообщении, включая отправителя или получателя, время отправки, тип сообщения, идентификатор ключа, и оригинальный текст сообщения для отправленных сообщений.

JavaScript-код в шаблоне обеспечивает динамическое обновление интерфейса без перезагрузки страницы, используя Fetch API для асинхронных запросов к серверу через REST API. Функции `updateIncomingMessages()` и `updateSentMessages()` периодически обновляют списки входящих и отправленных сообщений, отправляя GET-запросы к эндпоинтам `/api/get_incoming_messages` и `/api/get_sent_messages`. Функции обработки событий для кнопок "Дешифровать" и "Просмотр" отправляют POST-запросы к соответствующим эндпоинтам и обновляют интерфейс с результатами. Модальные окна управляются через JavaScript с обработчиками событий для открытия, закрытия, и взаимодействия с содержимым.

Стилизация интерфейса выполнена с использованием Tailwind CSS с дополнительными пользовательскими стилями для модальных окон, элементов сообщений, и анимаций. Классы CSS определяют внешний вид элементов, включая цвета фона, границы, отступы, скругления углов, и эффекты наведения. Адаптивный дизайн обеспечивает корректное отображение интерфейса на различных размерах экранов, с использованием flexbox-разметки для размещения элементов и overflow-свойств для прокрутки длинного контента.

## 12. Серверная часть (app.py)

Серверная часть системы реализована на основе фреймворка Flask, который обеспечивает обработку HTTP-запросов, управление сессиями пользователей, и рендеринг HTML-шаблонов. Модуль использует библиотеку `flask_cors` для разрешения кросс-доменных запросов между серверами, библиотеку `requests` для выполнения HTTP-запросов к удаленным серверам, стандартные библиотеки Python `threading`, `random`, `datetime`, и `time` для управления потоками, генерации случайных данных, и работы со временем. Flask-приложение инициализируется с секретным ключом для управления сессиями, подключается к базе данных SQLite через класс `DatabaseManager`, и инициализирует все модули системы, включая `QKDModule`, `KeyPostprocessingModule`, `KeyRecoveryModule`, `KeyManagementModule`, и `MessageCrypto`.

Серверная часть предоставляет множество маршрутов (routes) для обработки различных запросов от клиента. Маршруты аутентификации включают `/login` для входа пользователя в систему, `/register` для регистрации новых пользователей, и `/logout` для выхода из системы. Маршруты для работы с QKD включают `/generate_test_sequence` для генерации тестовых последовательностей, `/select_raw_key` для выбора сырого ключа, `/select_key` для выбора восстановленного ключа, и `/postprocess_key` для выполнения постобработки ключа по протоколу BB84. Маршруты для работы с сообщениями включают `/encrypt_message` для шифрования и отправки сообщений, `/decrypt_message` для дешифрования полученных сообщений, `/api/get_incoming_messages` для получения списка входящих сообщений, `/api/get_sent_messages` для получения списка отправленных сообщений, и `/api/view_sent_message` для просмотра деталей отправленного сообщения. Маршруты для синхронизации между серверами включают `/api/receive_encrypted_message` для приема зашифрованных сообщений от другого абонента, `/api/sync_sequence_selection` для синхронизации выбора последовательностей, `/api/sync_recovered_key` для синхронизации восстановленных ключей, и `/api/sync_key_destruction` для синхронизации уничтожения ключей.

Все маршруты используют систему сессий Flask для управления авторизацией пользователей, проверяя наличие `user_id` в сессии перед выполнением операций. Серверная часть также обеспечивает логирование всех операций через модуль `logging_utils`, форматирование данных для передачи клиенту через JSON, и обработку ошибок с возвратом соответствующих HTTP-кодов статуса. Конфигурация серверов задается через файл `config.py`, который определяет IP-адреса, порты, и адреса удаленных серверов для работы в локальной сети.
